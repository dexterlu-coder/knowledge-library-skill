# Knowledge Library · 飞书知识库助手

在 Codex 里说「收下这篇」，把文章、PDF 或个人笔记整理成带出处的知识卡，存进自己的飞书知识库。以后即使忘了文章标题，也可以直接问当时想解决的问题。Codex 会在指定的库里查找相关卡片，回读证据，并给出可打开的飞书链接。

## 安装与准备

1. 准备 Python 3.10 或更高版本。按飞书官方指南安装并配置 `lark-cli`，使用自己的飞书账号登录。这个账号需要能读取目标知识库、在选定页面下创建子页面，并编辑文档。[飞书 CLI 安装与授权指南](https://github.com/larksuite/cli)
2. 在终端运行 `lark-cli auth status --verify`，确认当前用户登录有效。
3. 把下面这句话发给 Codex。安装完成后重启 Codex。

   > 请用 $skill-installer 从 https://github.com/dexterlu-coder/knowledge-library-skill/tree/main/skills/knowledge-library 安装 knowledge-library。

## 从收录到找回

**选定保存位置。** 在飞书中打开准备存放卡片的知识库页面，复制链接，在 Codex 中发送下面这句话，并把占位文字换成自己的链接。这个选择保存在本机，以后开新会话也可以沿用。

> $knowledge-library 以后把资料存到我的「研究笔记」，入口是〈粘贴飞书知识库页面链接〉。

给出库入口时，Codex 会按这个库已有的约定归档。例如，一个库把方法卡集中保存，另一个库可能把它们放在各自的项目目录。要固定投到同一处，可以明确说「以后直接存到这个收件箱下面」，并附上该目录链接。

**收下第一份资料。** 假设你刚读完一篇关于访谈的 PDF，把它附在对话里，然后说：

> 收下这篇。把作者关于“什么时候可以停止访谈”的判断整理成卡片，标出页码，并把这份 PDF 作为附件保存。

Codex 会先列出库名和实际目录路径，再按每张卡能独立回答的问题整理材料。一个判断及其成立条件会保存在同一张卡里。写完后，它会回读正文、核对卡片所在目录，返回页面链接，并说明附件是否已核验。

**换个说法找回来。** 以后在同一台电脑上开一个新会话，就可以问：

> 从我的研究笔记里找一下：再访谈几个人也很难听到新信息时，怎么判断可以收尾？请给我卡片链接和原文页码。

## 保存位置、修订与重试

| 你可以这样说 | 会发生什么 |
| --- | --- |
| 「仅这次存到项目库，入口是……」 | 这份资料写到指定位置，下一次收录继续使用默认库。 |
| 「以后改存到团队知识库，入口是……」 | 在本机更新默认位置，后续收录使用新位置。 |
| 「把刚才那张卡的适用条件补充一下。」 | 按已有版本修订指定卡片。如果有人直接在飞书里改过正文，Codex 会展示差异，等你决定如何处理。 |
| 「继续上次没传完的 PDF，投递 ID 是……」 | 按原来的目标核对已保存内容，补传能确认缺失的附件。若上一次写入结果仍无法确认，回执会指出待核对项。 |

## 更新与本机数据

要使用仓库里的新版，可以让 Codex 执行：「从上面的 GitHub 安装地址更新已安装的 knowledge-library，完成后告诉我使用的是哪个提交。」手动安装的用户可下载仓库，将已安装的 `knowledge-library` 目录替换为新版的 `skills/knowledge-library`，然后重启 Codex。

知识卡保存在你授权的飞书页面下。本机另存默认位置、待写正文、投递记录和附件快照，供中断后续传。Windows 默认使用 `%LOCALAPPDATA%\knowledge-library`，其他系统使用 `$XDG_CONFIG_HOME/knowledge-library`，未设置相应变量时使用 `~/.config/knowledge-library`。更新 Skill 时可保留这份状态。[配置与投递流程](skills/knowledge-library/references/feishu.md)

当前版本支持飞书知识库的读写和检索。Obsidian 接入与跨库同步属于后续规划。
