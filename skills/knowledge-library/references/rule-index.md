# 规则卡与索引

适用于用户要维护项目规则卡的任务。用户只想保存供参考的经验时，按通用收录流程处理。

1. 在授权范围内确定规则向导。读取向导正文和全部直接子页，按卡号、主题和原页核对已有卡。选择未占用的卡号；修订沿用原卡号。若同号对应多个原页，先报告冲突。保留条件、例外、来源、版本和可直接采用的规则正文。
2. 按飞书投递流程写卡并回读正文和父目录。已有卡页或收到续办请求时，优先以页面链接或原投递 ID 核对已有结果，再处理索引。直接子页列表能验证归档位置；向导正文中的有效索引条目需要另外读取。
3. 比对向导正文中的条目与原页。每个卡号应有一条有效索引，包含正确的卡名、原页链接、适用条件和规则版本；组合示例中的卡号引用不算索引条目。匹配时直接复用。缺失时只新增该条，有旧条目时按核实的差异定点修改。遇到同号异页、重复条目或人工改动导致含义不清时保留原文并说明差异。
4. 用读取时的 revision_id 作条件，通过 docs +update 定点插入或更新，保留向导说明、其他条目及链接。版本冲突或写入结果不明时先回读当前正文，再按尚存差异处理，避免重复追加。完成后从向导逐条跟随链接，核对节点、父目录、版本和选用条件。
5. 卡页和索引分别回执。卡页已完成而索引未核实时，明确写「卡片已保存，索引待同步」，附向导、卡号、原页、版本、投递 ID 和原因，供下一会话接续；重试只补缺项。两者均通过后才报告规则卡入库完成。为项目选卡仍按检索流程比对索引与真实子页。
