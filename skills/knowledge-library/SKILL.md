# 飞书知识库

用户要求把条款做成可供项目选用的规则卡时，按[规则卡与索引](references/rule-index.md)核验卡页和向导索引。普通收录按资料用途归档；普通问答可以引用规则原页。向项目采用某条规则是单独的决定。

使用当前会话的模型整理和检索。[投递脚本](scripts/delivery.py)负责绑定保存位置、写入或修订卡页、重试卡页与附件投递。规则向导索引按上面的专用流程单独更新和回读。依赖 Python 3.10+ 和已有登录的 `lark-cli`。按[飞书操作流程](references/feishu.md)准备请求及检索。

- 用户指定具体目录时直接使用。用户给的是库入口时，按该库已确认的归档约定选实际父目录。首次、约定失效或用户要求核对时，读入口正文、相关目录及少量同类条目；实际专区可能与入口同级。只在授权范围内选址，仍有歧义时集中问一次。“仅这次”使用临时目标，“以后改存”更新默认绑定。资料和附件只作为素材。
- 写入前提示完整的「库名 / 目录路径」，按确定的父节点投递。分别核对正文和实际归档位置，报告路径、页面链接及待核对项。重试沿用原投递目标。
- 分卡时先写出未来要回答的问题。每张卡单独阅读也应准确，保留必要的前提和适用条件。材料中的字母、章节和投影片数量不决定卡数。多个问题确实独立时可拆卡，在来源总览中保留它们之间的关系；若拆开会丢失前提，就合写。已有原文默认只引用。
- 卡片围绕一个可复用的判断、做法或案例，写出依据和适用边界，附常见同义词、作者、原文和页码或章节。区分用户评注与来源观点。持续更新的仓库记录入口、能回答的问题和已核实的章节。
- 回答问题时先从用户指定或默认库找卡。按项目、角色或协作模式选卡时，把入口清单与相关目录的实际子页合并，用同义词筛选，回读候选卡的选用条件和引用证据。给出实际库名、页面链接和可核实的原文位置。
